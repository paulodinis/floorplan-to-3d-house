# Blender drone video (Blender 4.2+ / 5.x, Cycles)

Requirements:
- Blender with an MCP add-on (server started) on the user's machine, reachable through the Blender MCP;
- a GPU (OptiX / CUDA / HIP / Metal);
- the project folder on that machine.

1. **GLB transfer:** device file transfers may be capped (~30 MB). Split the file (`split -b 15000000`), copy the parts and join them in Blender Python.
2. **params.json:**
   - `dir`, `glb`, `blend`, `scripts_dir` (the skill's `scripts/blender` copied to the PC);
   - `window` (detailed ground window), `spots`, `ffl`;
   - `camera_keys: [[frame, [x, y, z], [tx, ty, tz]]]` in scene coordinates and `doors: [{x, z, y0, w, kind, frame, toward}]`, both from `camera_path.py`;
   - `frames_src` / `frames_out`, `res`, `samples`;
   - `sun {lat, dec, hour, north_deg}`;
   - `room_lights [[x, y, z]]`, `outdoor_zones`;
   - optional `haze_start`, `haze_depth`, `haze_max`, `haze_color`.
3. **Build in the background.** MCP calls time out at about 60 s:
   `blender -b --python run_<project>.py`, where the driver joins the GLB, loads params and runs `run_all.py`. The passes are:
   - import (the KHR_materials_volume extension is stripped);
   - join by material;
   - materials;
   - scatter (grass, olive leaves, hedges, lavender);
   - physical sky + sun;
   - interior lights;
   - doors on the camera path (`doors.py`: leaves split, pivot on the hinge, 95° swing toward the next room);
   - surrounding terrain from the spot heights;
   - style (`style.py`: only when `params.json` has `"restyle"`, see style-guide.md);
   - haze;
   - final settings.
4. **Camera path:** generated by `scripts/cloud/camera_path.py` (every video: 360° orbit; 60 s: orbit + front door + the doorway of every space, doors in `doors`, opened by `doors.py`). When adjusting it by hand:
   - test canopy clearance numerically: horizontal distance to each tree > crown radius + 0.5 m whenever the camera is below the canopy top;
   - keep low cameras off saw-toothed mesh edges such as the asphalt boundary;
   - in walkthroughs:
     - open the doors on the path (`rotation_mode='XYZ'`, origin moved to the hinge);
     - keep the eye 1.5–1.7 m above the floor;
     - keep clear of door heads (opening head ~2.1–2.4 m above that floor).
5. **Test frames:**
   - 50 % resolution, 48 samples, 5–6 frames at the keys;
   - copy them back and look at them;
   - fix framing, obstructions and missing parts.
6. **Measure:** read `Time:` in the log and quote frames × s/frame. Examples (RTX 4060, 1600×900, 24 samples, haze): 15 s ≈ 3 h 15, 60 s ≈ 12 h 45.

### Resolution and time estimates (ask before rendering)
25 fps, Cycles 24 samples with haze, reference GPU RTX 4060. 1600×900 was measured; the other two are scaled by pixel count (1920×1080 = 1.44×, 1280×720 = 0.64×), so treat them as estimates until a test frame is measured on the user's machine. Render time grows roughly with pixel count; other GPUs scale in proportion.

| Resolution | s/frame (est.) | 15 s (375 fr.) | 30 s (750 fr.) | 60 s (1500 fr.) |
|---|---|---|---|---|
| 1920×1080 | ~45 s | ~4 h 40 | ~9 h 25 | ~18 h 45 |
| 1600×900 (recommended) | ~31 s (measured) | ~3 h 15 | ~6 h 30 | ~12 h 55 |
| 1280×720 | ~20 s | ~2 h 05 | ~4 h 10 | ~8 h 20 |

When quoting, show the row for the chosen length and replace the estimate with the measured s/frame after the test frames (step 5).
7. **Final:**
   - render in a subprocess: `blender -b <blend> -o <dir>/frames/f_ -a`;
   - start the watcher: `CS_DIR=<dir> CS_TOTAL=<frames> CS_OUT=<name>_ blender -b --factory-startup --python encode.py`, which writes the MP4 (H.264) and `<name>_DONE.txt`;
   - schedule a check, if the host supports it;
   - tell the user to keep the PC awake.


## Open the model in Blender (Step 7b)
`scripts/blender/open_in_blender.py` takes the GLB and the `.blend` to write, either after `--` on the command line or as `ARGS` in `init_globals`.
- **Blender MCP connected:** `import runpy; runpy.run_path(r"<dir>/open_in_blender.py", init_globals={"ARGS": [r"<dir>/<name>.glb", r"<dir>/<name>.blend"]})`.
- **Blender open, MCP not connected (computer use):** grant Blender (on Windows the window belongs to `blender.exe`, not `blender-launcher.exe`). Click the 3D view, press `Shift+F4` (Python console) and type the line below, wrapped in a timer so the 3D view is back when it runs. Press Enter, then `Shift+F5`:
  `import bpy, runpy; bpy.app.timers.register(lambda: runpy.run_path(r"<dir>/open_in_blender.py", init_globals={"ARGS": [r"<dir>/<name>.glb", r"<dir>/<name>.blend"]}) and None, first_interval=3.0)`
  The script clears the scene: only do this when the open scene is empty or saved.
- **Blender closed:** write a launcher next to the GLB and open it with computer use (File Explorer is click-only: double-click it) or ask the user to double-click it.
  - Windows `open_<name>_blender.bat`: `start "" "C:\Program Files\Blender Foundation\Blender <ver>\blender.exe" --python "<dir>\open_in_blender.py" -- "<dir>\<name>.glb" "<dir>\<name>.blend"`.
  - macOS `.command`: `/Applications/Blender.app/Contents/MacOS/Blender --python ...`.
  - Ask for the Blender path if it isn't there.
- **MCP add-on:** the script calls the first `start` operator it finds in an `*mcp*` operator namespace: BlenderMCP `blendermcp.start_server`, or the "MCP" extension `blmcp.server_start`. "Server is already running" counts as started.
- **Output:** `<name>_blender_open.json` with `objects`, `camera`, `blend` and `mcp`.


## Blender MCP on Windows (Smart App Control)
Symptom: the Blender add-on server is running ("Server is already running"), but the client in the Claude app stays "failed / Connection closed". Windows Security shows "Part of this app has been blocked … can't confirm who published blender-mcp.exe" (under `uv-runtime`).
Cause: Smart App Control blocks the unsigned `blender-mcp.exe` launcher that `uvx` generates. It has no per-app allow list, and approving the notification does not stick.
Fix (keeps Smart App Control on): run the same server through the signed Python interpreter.
1. `py -m pip install blender-mcp` (or `python -m pip install --user blender-mcp`).
2. Claude app → Settings → Developer → Edit config (`%APPDATA%\Claude\claude_desktop_config.json`). The "blender" entry becomes:
   ```json
   "blender": { "command": "py", "args": ["-c", "from blender_mcp.server import main; main()"] }
   ```
   Use the full path of `python.exe` if `py` is missing.
3. Quit the Claude app completely (tray icon → Quit) and reopen it. In Blender, start the add-on server.
The user makes the config edit. The session cannot open Claude's settings folder, and must not try to edit it through Blender or another process.
`blender-mcp` speaks the BlenderMCP add-on protocol (ahujasid/blender-mcp `addon.py`, "Connect to Claude"). If another MCP extension is installed instead (e.g. the "MCP" extension, `blmcp.server_start`), the client may connect and drop: install the BlenderMCP add-on.


## One launcher: `scripts/blender/pipeline.py` (1.6.0)
One MCP call starts it detached, then poll one small JSON. It replaces the per-project driver scripts.
```python
# in execute_blender_code (live session); Windows flags = detached + no console window
import subprocess, sys, bpy
subprocess.Popen([sys.executable, r"<scripts_dir>\pipeline.py", "test", r"<dir>\params.json", bpy.app.binary_path],
                 creationflags=0x00000008 | 0x08000000, close_fds=True)
```
- `build`: GLB → all passes (`run_all.py`) → `<blend>`.
- `test`: build, then 8 frames spread over the video + the frame after each door opens, at 50 % / 48 samples. Writes one contact sheet `tests/sheet.jpg` (4 columns, 480 px tiles; the red bar on top shows the position in the video), `tests/times.json` and `s_per_frame_est` (×4 pixels, ×samples/48). `"test_frames": [..]` in params.json to re-test only some frames.
- `final`: build, start `encode.py` (waits for the frames, writes `<video_name>*.mp4` and `<video_name>DONE.txt`), render all frames. While rendering it keeps `frames_done`, measured `s_per_frame` and `eta_h` up to date.
- `check`: print the status (no Blender).
- Status `<dir>/pipeline_status.json`: `mode`, `stage`, `ok`, `error`, `build` (the `run_all.py` result, including `doors.py` → `missing` / `suspicious`), `test`, `s_per_frame_est`, `frames_done`, `eta_h`, `mp4`. Logs `pipeline_<stage>.log` only when the status shows an error.
- `blender-launcher.exe` is swapped for `blender.exe` next to it (the launcher returns at once).

## The user's own camera path: `scripts/cloud/camera_script.py` (1.6.0)
Turn a shot list in words into steps in `path.json`; durations are relative and scaled to `seconds`. Example (90 s, Casa Sobreiral v15):
```json
{"seconds": 90, "steps": [
 {"do": "start", "dist": 4, "eye": 1.2, "t": 1.5, "label": "Low, facing the front door"},
 {"do": "orbit_in", "radius": 27, "height": 13, "t": 5.5}, {"do": "orbit", "deg": 360, "t": 22},
 {"do": "to_door", "t": 4}, {"do": "move", "to": {"room": "Hall"}, "t": 2},
 {"do": "move", "to": {"room": "Suite", "frac": 0.6}, "via": [{"xz": [-6.9, -0.57]}], "t": 3.5},
 {"do": "pivot", "deg": 45, "t": 1.5}, {"do": "pivot", "deg": -90, "t": 2},
 {"do": "move", "to": {"room": "Suite bathroom"}, "via": [{"room": "Closet"}], "t": 4.5},
 {"do": "pivot", "deg": 180, "t": 1.5}, {"do": "move", "to": {"stair": "top"}, "t": 4},
 {"do": "stairs", "t": 2.5}, {"do": "forward", "m": 1.5, "t": 1.5},
 {"do": "turn_to", "look": {"xz": [6.5, -3.4]}, "t": 2}, {"do": "spin", "deg": 360, "radius": 0.5, "t": 7.5},
 {"do": "move", "to": {"xz": [9, 5]}, "t": 3.5}, {"do": "rise", "up": 1, "back": 3, "look": {"xz": [8.2, 4.2]}, "t": 3},
 {"do": "strafe", "to": {"xz": [18, 3.2]}, "via": [{"xz": [13.6, 9.2]}], "look": {"xz": [14.4, -3.3]}, "t": 4.5},
 {"do": "aerial", "height": 40, "t": 4.5}]}
```
Lessons from that video:
- From 0.8 m back, a narrow doorway shows only jambs: step onto the threshold.
- Small rooms (closets of 1.2 m, a 1.5 m bathroom) show mostly walls: keep them short, or skip them.
- Leaving through glass is allowed but listed in `checks`: say so to the user.
- Keep the eye under eaves (≈ 2.4 m above a porch floor) or the roof fills the frame.
- Go round columns with a `via` point.
- Look back at the house after stepping outside, not at the lawn.

## Blender MCP (troubleshooting)
- Live session: "Cannot connect to Blender at localhost:9876". Blender is closed, or its MCP add-on server isn't started. Ask the user to open Blender and start the add-on server.
- Background mode (`execute_blender_code_for_cli`) needs `BLENDER_PATH` in the MCP's settings. `pipeline.py` doesn't need it: it takes the executable from `bpy.app.binary_path` of the live session.
- Doors that open only in part: `doors.py` groups loose parts by shared edges *and* coincident vertices (the GLB writes split vertices); `suspicious` in its result lists leaves whose size doesn't match the opening.

## Optional passes (1.8.0)
- `"extra_passes": ["soften.py", "lens.py"]` in params.json runs extra passes after `doors.py`.
- `soften.py`: rounded edges on furniture and cars (Bevel, angle-limited), puffier cushions, pillows and duvets, fabric weave + wrinkles as bump. Radii in `"soften": {"edge": 0.012, "soft": 0.035, "car": 0.06}`. About +10 % render time.
- `lens.py`: animates the focal length from `"lens_keys": [[frame, mm], ...]`; use 16 mm indoors (from the front door to the exit) and 22 mm outside, so small rooms show more than one wall.
- `camera_script.py --eye 1.5` sets the walking eye height (default 1.6 m; 1.5 m = eyes of a 1.60 m person).
- `pipeline.py` always builds with `render: false`: it renders the frames itself. (Before 1.8.0, `"render": true` in params.json started a second, hidden render during the build and doubled the time per frame.)

## 1.8.4
- **GPU rendering:** `pipeline.py` turns on the GPU (OptiX, else CUDA / HIP / Metal / oneAPI) inside the render and test processes, without saving the user's preferences. A background Blender reads the preferences; with the compute device at "None" Cycles rendered on the CPU, about 4–5× slower (RTX 4060: ~18 s → ~4 s per frame at 1600×900, 24 samples). The log prints `RENDER_DEVICE`. `"start_frame"` in params.json resumes a stopped render.
- **Sun:** the sky's `sun_rotation` now matches the Sun lamp (Blender measures it from +Y toward +X); before, the sky glow and the sun disc sat mirrored against the shadows.
- **`daycycle.py`** (optional pass): `"sun_anim": {"f0", "f1", "hour0", "hour1"}` animates the solar time between two frames: lamp direction, colour and strength, sky sun, background and exposure, with a soft moon at night. Use it for a day-to-night aerial orbit.
- **`outdoor_zones`** now defaults to none: outdoor furniture (porch tables, sofas, loungers) is kept. Give rects only to delete furniture inside them.
- **`camera_script.py --linear`**: constant speed inside each step. For a calm, even walk set each step's `t` from its length (≈ 1 m/s on foot, 3–4 m/s for the drone, turns ≈ 30°/s) and pass `--linear`; a light 0.5 s moving average on the keys smooths the corners.
